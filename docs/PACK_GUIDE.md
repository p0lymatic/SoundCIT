## Как это работает в двух абзацах

Мод слушает **каждый** звук, который собирается проиграть клиент, и пытается понять, каким предметом
этот звук вызван. Если предмет удалось определить и у него есть кастомное имя, совпадающее с вашим
правилом, — звук подменяется на ваш.

Определить предмет не всегда просто: большинство звуков сервер присылает пакетом, где написано
только «проиграй такой-то звук в такой-то точке», без единого слова о предмете. Поэтому мод
использует несколько независимых способов установить источник, от самых надёжных к наименее. От
того, какой способ сработал, зависит надёжность подмены — подробности в разделе
[«Насколько надёжно что подменяется»](#насколько-надёжно-что-подменяется).

## Пак за пять минут

Задача: сделать так, чтобы булава с именем **Сковородка** звенела как сковородка.

**1.** Создайте папку пака и в ней `pack.mcmeta`:

```json
{
  "pack": {
    "pack_format": 34,
    "description": "Мои звуки"
  }
}
```

**2.** Положите звук в `assets/mypack/sounds/frying_pan.ogg`.

**3.** Опишите звук в `assets/mypack/sounds.json`:

```json
{
  "frying_pan": {
    "sounds": ["mypack:frying_pan"]
  }
}
```

**4.** Создайте правило `assets/mypack/soundcit/frying_pan.json`:

```json
{
  "item": "minecraft:mace",
  "pattern": "Сковородка",
  "sounds": {
    "hit": "mypack:frying_pan"
  }
}
```

**5.** Включите пак, назовите булаву в наковальне «Сковородка», ударьте моба.

Правку правил и звуков подхватывает **F3+T** — перезапускать игру не нужно.

## Структура пака

```
MyPack/
├── pack.mcmeta
└── assets/
    └── mypack/                      ← ваш namespace, любое имя латиницей
        ├── sounds.json              ← описание звуков для Minecraft
        ├── sounds/
        │   ├── frying_pan.ogg
        │   └── mjolnir_thunder.ogg
        └── soundcit/                ← правила SoundCIT
            ├── frying_pan.json
            └── mjolnir.json
```

Мод читает **все** файлы `.json` из папки `soundcit/` в **любом** namespace всех активных паков.
Имена файлов ни на что не влияют — называйте как удобно. Можно разложить по подпапкам,
`soundcit/weapons/mace.json` тоже подхватится.

Правила из разных паков складываются. Если два пака описывают один и тот же предмет, побеждает тот,
у кого выше [`priority`](#priority--кто-победит).

## Формат правила

Минимальное правило состоит из `pattern` и `sounds`:

```json
{
  "item": "minecraft:mace",
  "match": "custom_name",
  "pattern": "Frying Pan",
  "priority": 0,
  "sounds": {
    "hit": "mypack:frying_pan_hit",
    "attack": "mypack:frying_pan_swing"
  }
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `item` | нет | Какие предметы. Строка или массив строк. Без него правило применяется к **любому** предмету с подходящим именем. |
| `match` | нет | Сейчас поддерживается только `custom_name` (значение по умолчанию). Задел на будущее. |
| `pattern` | **да** | Как сравнивать кастомное имя предмета. |
| `priority` | нет | Число, по умолчанию `0`. Кто победит, если подходят несколько правил. |
| `sounds` | **да** | Что на что менять. Пустой объект — ошибка. |

### `item` — какие предметы

```json
"item": "minecraft:mace"
```

```json
"item": ["minecraft:iron_sword", "minecraft:golden_sword", "minecraft:diamond_sword"]
```

Поле можно вообще опустить — тогда правило сработает для любого предмета, лишь бы имя совпало.
Это удобно для «глобальных» правил вида «всё, названное *Проклятое*, звучит зловеще», но будьте
осторожны: такое правило конкурирует со всеми остальными.

### `pattern` — как сравнивать имя

Сравнивается **видимое имя** предмета — то, что вы вводите в наковальне или задаёте компонентом
`minecraft:custom_name`. Форматирование (цвет, курсив) не учитывается, сравнивается чистый текст.

| Синтаксис | Поведение |
|---|---|
| `Frying Pan` | Точное совпадение, **без учёта регистра**. `frying pan` тоже подойдёт. |
| `pattern:Frying*` | Маска: `*` — любой отрезок, `?` — один символ. С учётом регистра. |
| `ipattern:frying*` | То же, но без учёта регистра. |
| `regex:^Меч .*$` | Регулярное выражение, с учётом регистра. |
| `iregex:^меч .*$` | Регулярное выражение без учёта регистра. |

Маска и регулярное выражение проверяются на **полное** совпадение со всем именем, а не на вхождение.
Чтобы найти слово внутри имени, обрамите звёздочками: `ipattern:*молот*`.

Примеры:

```json
"pattern": "Мьёльнир"
"pattern": "ipattern:*сковород*"
"pattern": "regex:^Клинок (Зари|Заката)$"
```

### `sounds` — чем заменять

Объект «что менять» → «на что менять». Ключ — [семантический триггер](#полный-список-триггеров)
или [прямой id ванильного звука](#прямая-замена-по-id-звука). Значение — id вашего звука из
`sounds.json`.

```json
"sounds": {
  "hit": "mypack:frying_pan_hit",
  "attack": "mypack:frying_pan_swing",
  "item_break": "mypack:frying_pan_snap"
}
```

Указывайте только те триггеры, которые нужны, — остальные звуки останутся ванильными.

### `priority` — кто победит

Если предмет подходит сразу под несколько правил, выигрывает правило с **бо́льшим** `priority`.
При равном приоритете порядок определяется путём файла — то есть предсказуем и не меняется от
запуска к запуску, но полагаться на него не стоит: если правила конкурируют осознанно, задайте
приоритеты явно.

```json
{ "pattern": "*", "priority": -10, "sounds": { "hit": "mypack:generic" } }
```

Такое правило-подложка сработает только там, где не сработало ничего более конкретного.

## Прямая замена по id звука

Если нужного триггера нет или хочется точности, ключом можно указать **полный id ванильного
звука** — всё, что содержит двоеточие, считается прямым правилом:

```json
"sounds": {
  "minecraft:item.mace.smash_ground_heavy": "mypack:earthquake",
  "minecraft:item.trident.thunder": "mypack:thor"
}
```

Прямое правило **приоритетнее** семантического триггера: если под звук подходят оба, победит прямое.
Это позволяет задать общее поведение триггером и выборочно переопределить частный случай:

```json
"sounds": {
  "hit": "mypack:generic_hit",
  "minecraft:item.mace.smash_ground_heavy": "mypack:heavy_smash"
}
```

Так работает и с моддовыми звуками: `"othermod:item.hammer.smash": "mypack:clang"`.

## Требования к звуковым файлам

- Формат — **Ogg Vorbis** (`.ogg`). Другие форматы Minecraft не читает.
- Для **позиционных** звуков (а это почти все звуки предметов) файл обязан быть **моно**.
  Стерео-файл будет слышен одинаково громко со всех сторон, без привязки к месту.
- Частота дискретизации — обычно 44100 Гц.
- Файл кладётся в `assets/<namespace>/sounds/`, а в `sounds.json` указывается путь **без**
  расширения и без папки `sounds/`.

Пример `sounds.json` с несколькими вариантами звука (Minecraft выберет случайный):

```json
{
  "frying_pan_hit": {
    "sounds": [
      "mypack:frying_pan_hit1",
      "mypack:frying_pan_hit2",
      "mypack:frying_pan_hit3"
    ],
    "subtitle": "mypack.subtitle.frying_pan"
  }
}
```

Субтитр (`subtitle`) не обязателен, но без него при включённых субтитрах будет пусто.
Строку для него добавьте в `assets/<namespace>/lang/ru_ru.json`.

Регистрировать звуки как `SoundEvent` через код **не нужно** — достаточно `sounds.json`.

## Отладка

Три клиентские команды:

| Команда | Что делает |
|---|---|
| `/soundcit list` | Показывает загруженные правила и режим (клиентский или с поддержкой сервера) |
| `/soundcit debug` | Включает подробный лог: какие кандидаты перебирались и почему не подошли |
| `/soundcit why` | Последние подмены с указанием слоя, которым определён предмет |

Типичный цикл отладки: включили `/soundcit debug`, воспроизвели действие, посмотрели `latest.log`.
В логе будет либо строка подмены, либо объяснение отказа — например
`«звук подходит под правило, но предмет не определён»`.

В выводе `/soundcit why` слой означает:

| Слой | Что это | Насколько верить |
|---|---|---|
| `server` | Сервер прямо сказал, какой предмет вызвал звук | Факт |
| `entity` | Предмет взят у сущности, к которой привязан звук | Факт |
| `context` | Клиент предсказал действие заранее | Обычно верно |
| `proximity` | Найдена подходящая сущность рядом со звуком | Догадка |

## Насколько надёжно что подменяется

Не все звуки одинаково легко привязать к предмету. Полезно понимать, чего ожидать.

**Работает всегда, даже на ванильном сервере:**
ближний бой, еда и питьё, копание и постановка блоков, инструменты по блокам (мотыга, топор,
лопата, огниво, воск, костная мука), вёдра и бутылки, подзорная труба, козлий рог, сумка,
поломка предмета, трезубец в полёте (возврат, попадание, втыкание).

**Своё работает, чужое — только с модом на сервере:**
тотем, блок щитом, надевание брони, стрижка. Для собственных действий клиент знает достаточно, для
чужих сущностей — нет.

**Только с модом на сервере:**
попадание стрелы с учётом того, **из какого лука** она выпущена. Оружие, из которого выпущен снаряд,
клиенту не синхронизируется в принципе — без серверной части эту связь установить неоткуда.

**Может не сработать:**

- `trident_throw` — звук привязан к только что созданному снаряду, о котором клиент иногда ещё не
  знает; в этом случае ванилла отбрасывает звук молча, подменять нечего. Возврат и попадание
  трезубца надёжны.
- Станки (`anvil`, `grindstone`, `smithing`, `enchant`) и `bone_meal`/`wax_on` — идут особым путём,
  где предмета в момент проигрывания нет вовсе; привязка делается по позиции блока.
- При очень большом пинге предсказанные действия могут не успеть: контекст живёт около секунды.

**Намеренно не подменяется:** музыка, пластинки, эмбиент и голосовые категории — их мод не трогает
вообще. И если рядом два игрока с одинаково подходящими предметами, а определить точнее нельзя, мод
предпочтёт **не** подменять: украсть чужой звук хуже, чем пропустить свой.

## Мод на сервере

Ставить SoundCIT на сервер **не обязательно** — на ванильном сервере он работает.

Если поставить, точность вырастет: сервер сообщает клиенту, какой предмет вызвал звук, и догадки
заменяются фактами. При этом **правила остаются вашим личным делом** — сервер их не видит и не
раздаёт, у каждого игрока может быть свой пак.

Совместимость не ломается ни в одну сторону: ванильный клиент зайдёт на сервер с модом, а клиент с
модом — на ванильный сервер.

Проверить, работает ли серверная поддержка: `/soundcit list` покажет `server-assisted` или
`client-only`.

## Частые ошибки

**Звук не меняется, в логе тишина.**
Правило не загрузилось. Проверьте `/soundcit list` — если правила нет, ошибка в JSON (мод пишет
причину в лог при загрузке) или файл лежит не в `assets/<namespace>/soundcit/`.

**Правило загружено, но звук ванильный.**
Скорее всего имя не совпало. Регистр в простом `pattern` не важен, но лишние пробелы важны.
Включите `/soundcit debug` и посмотрите, определяется ли предмет вообще.

**Звук играет отовсюду одинаково громко.**
Файл в стерео. Пересохраните в моно.

**Заменился не тот звук.**
Триггеры перекрываются: например `hit` включает и обычное попадание, и удар булавы. Возьмите
[прямую замену по id](#прямая-замена-по-id-звука) вместо триггера.

**Работает у вас, но не у других игроков.**
Так и задумано: пак стоит только у вас. Чтобы слышали все, пак нужен каждому.

**Ничего не меняется после правки файлов.**
Нажмите F3+T. Если не помогло — пак не активен в настройках, либо игра читает старую копию из
`resourcepacks/`.

## Условия: не только имя

Помимо имени правило может требовать от предмета чего-то ещё. Все указанные условия должны
выполняться одновременно.

```json
{
  "item": "minecraft:diamond_sword",
  "pattern": "Клинок Зари",
  "enchantments": { "minecraft:sharpness": ">=4" },
  "damage_percent": "<50",
  "sounds": { "hit": "mypack:dawn_hit" }
}
```

| Поле | Что проверяет | Примеры |
|---|---|---|
| `enchantments` | Уровень чар (0 — значит чар нет) | `{"minecraft:sharpness": ">=4"}`, `{"minecraft:mending": "1"}` |
| `damage` | Абсолютный износ | `"0"`, `">100"`, `"1-50"` |
| `damage_percent` | Износ в процентах от прочности | `"<50"`, `">=90"` |
| `count` | Размер стопки | `"1"`, `">=16"` |
| `tag` | Тег предмета | `"#minecraft:swords"` |
| `components` | Компоненты, которые должны быть | `["minecraft:enchantment_glint_override"]` |
| `without_components` | Компоненты, которых быть не должно | `["minecraft:unbreakable"]` |

Числа пишутся как в CIT: точное значение (`4`), сравнение (`>=4`, `<50`, `>3`) или диапазон (`1-3`).

**Поле `pattern` при наличии условий необязательно** — правило может отбирать предметы вообще без
оглядки на имя, например «любой алмазный меч с Остротой выше четвёртой». Но правило совсем без
`pattern`, `item` и условий отвергается: оно совпадало бы со всем подряд.

**Важное ограничение.** Условия требуют самого предмета, а часть звуков опознаётся только по имени и
типу — так устроен, например, летящий трезубец. Для таких звуков правило с условиями **не
применяется**: лучше пропустить подмену, чем угадать неверно.

## Конструктор паков в терминале

В репозитории есть `tools/soundcit-pack.py` — он избавляет от ручной сверки трёх файлов между собой
и, главное, умеет находить несостыковки.

```bash
# создать пустой пак (номер формата подставится по версии игры)
tools/soundcit-pack.py new MyPack --namespace mypack --mc-version 26.2

# добавить правило и сразу втянуть звук: сконвертирует в моно vorbis, как требуется
tools/soundcit-pack.py add MyPack --item minecraft:mace --name "Frying Pan" \
                                  --sound hit=pan_hit --file ~/pan.wav

# проверить, что все ссылки разрешаются
tools/soundcit-pack.py check MyPack

# собрать архив
tools/soundcit-pack.py build MyPack

# напомнить список триггеров
tools/soundcit-pack.py triggers
```

Самая полезная команда — `check`. Она ловит то, что в игре проявляется как необъяснимая тишина:
звук объявлен в `sounds.json`, но `.ogg` не положен; в правиле указан звук, которого нет в
`sounds.json`; забыт namespace; опечатка в имени триггера; неподходящий `pack_format`.

Для конвертации аудио нужен `ffmpeg`, всё остальное работает на голом Python.
