# SoundCIT

**CIT (Custom Item Textures), но для звуков.** NeoForge 1.21.1, клиентский мод.

Переименуйте предмет (наковальней или командой) так, чтобы имя совпало с правилом из
ресурспака — и вместо ванильных звуков предмет начнёт издавать кастомные звуки из ресурспака.

Пример из коробки: булава (mace), переименованная в **"Frying Pan"**, при ударе звенит как
сковородка, а при промахе — свистит.

## Как это работает

Подмена всегда происходит в одной точке — `PlaySoundEvent`, единственном месте, которое видит
**все** звуки клиента. Вопрос лишь в том, откуда узнать, какой предмет виноват. Источники
опрашиваются по убыванию достоверности:

1. **Подсказка сервера** (если мод стоит и на сервере) — точное имя предмета, привязанное к
   конкретному звуку по его `seed`. Никаких догадок.
2. **Сущность-источник звука.** Мини-миксины в `ClientLevel` перехватывают эмиссию звука и
   сохраняют сущность, точную позицию и seed, которые к моменту `PlaySoundEvent` уже потеряны.
   Дальше предмет ищется в нужном слоте этой сущности (щит — в используемом, броня — в слотах
   брони, тотем — в руках).
3. **Предсказанный контекст.** Клиентские хуки действий (`AttackEntityEvent`,
   `UseItemOnBlockEvent`, `LivingEntityUseItemEvent`, ...) записывают «предмет X сейчас вызовет
   звук», с TTL в тиках и привязкой к сущности.
4. **Поиск по позиции** — последний шанс: сущность рядом со звуком. Если подходящих кандидатов
   несколько и они дают разный результат, подмена не делается: украсть чужой звук хуже, чем
   пропустить свой.

Летящий трезубец опознаётся особым образом: его `ItemStack` на клиент не синхронизируется, зато
кастомное имя копируется на саму сущность-снаряд — по нему и определяется «Мьёльнир».

## Формат правил

`assets/<любой-namespace>/soundcit/<имя>.json` в любом активном ресурспаке (или в jar мода):

```json
{
  "item": "minecraft:mace",
  "match": "custom_name",
  "pattern": "Frying Pan",
  "sounds": {
    "attack": "mypack:frying_pan_swing",
    "hit": "mypack:frying_pan_hit",
    "minecraft:item.mace.smash_ground_heavy": "mypack:frying_pan_hit"
  }
}
```

- **`item`** — id предмета или массив id. Можно опустить — правило применится к любому предмету.
- **`match`** — пока поддерживается только `custom_name` (имя, заданное наковальней или
  компонентом `minecraft:custom_name`).
- **`pattern`** — как сравнивать имя:
  - обычная строка — точное совпадение без учёта регистра;
  - `pattern:Frying*` / `ipattern:...` — маска с `*` и `?`;
  - `regex:...` / `iregex:...` — регулярное выражение.
- **`priority`** — число (по умолчанию 0). Если предмет подходит под несколько правил, выигрывает
  правило с бо́льшим приоритетом; при равенстве порядок определяется путём файла (детерминированно).
- **`sounds`** — ключ → id звука-замены (обычный звук из `sounds.json` ресурспака,
  регистрация `SoundEvent` не нужна). Ключом может быть либо полный id ванильного звука
  (`minecraft:item.mace.smash_ground`) — прямая замена, либо один из семантических триггеров:

| Категория | Ключи |
|---|---|
| Ближний бой | `attack` (замах/промах), `hit` (попадание, вкл. удар булавы) |
| Использование | `use`, `eat`, `drink`, `chorus_teleport` |
| Добыча и постройка | `mine`, `break`, `place` |
| Стрельба | `shoot`, `throw`, `crossbow_load`, `crossbow_load_end`, `arrow_hit` |
| Трезубец | `trident_throw`, `trident_return`, `trident_hit`, `trident_hit_ground`, `riptide`, `thunder` |
| Защита | `shield_block`, `shield_break`, `totem_use` |
| Состояние предмета | `equip`, `item_break`, `elytra` |
| Рыбалка | `fish_cast`, `fish_retrieve`, `fish_splash` |
| Ёмкости | `bucket_fill`, `bucket_empty`, `bottle_fill`, `bottle_empty` |
| Инструменты по блоку | `till`, `strip`, `scrape`, `wax_on`, `wax_off`, `flatten`, `brush`, `ignite`, `bone_meal`, `dye`, `shear` |
| Прочее | `spyglass`, `instrument`, `bundle` |
| Станки | `anvil`, `grindstone`, `smithing`, `enchant` |

Звуки-замены — обычные записи `sounds.json` + `.ogg` (vorbis) в ресурспаке.

## Горячая перезагрузка

Правила перечитываются по **F3+T** (обычный resource reload) — пересобирать мод для правки
правил и звуков не нужно.

## Команды (клиентские)

- `/soundcit list` — показать загруженные правила.
- `/soundcit debug` — подробный лог захвата контекстов и подмен (или `-Dsoundcit.debug=true`).

## Проверка в игре

```
/give @s minecraft:mace
/item modify entity @s weapon.mainhand {function:"minecraft:set_name",entity:"this",name:{text:"Frying Pan"},target:"custom_name"}
```
(или просто переименуйте булаву в наковальне в `Frying Pan`)

Ударьте моба — услышите звон сковородки; промахнитесь с замахом — свист.

## Мод на сервере (необязательно)

Мод работает на **ванильном сервере** — вся логика клиентская. Но если поставить его и на сервер,
точность вырастет: сервер сообщает клиенту, какой предмет вызвал каждый звук (только id предмета и
имя, не весь стек, и только для предметов с кастомным именем — трафик практически нулевой).

Правила при этом остаются **личным делом клиента**: сервер их не видит и не синхронизирует, так что
у разных игроков могут быть разные ресурспаки.

Канал зарегистрирован как `optional`, поэтому совместимость не ломается ни в одну сторону:
ванильный клиент зайдёт на сервер с модом, а клиент с модом — на ванильный сервер.

Что даёт только серверная часть:
- звуки **других** игроков и мобов (чужой тотем, чужой блок щитом);
- экипировка брони через инвентарь (звук играется только на сервере);
- попадание стрелы с учётом того, **из какого лука** она выпущена (оружие снаряда клиенту не
  синхронизируется вообще).

## Ограничения

- Подменяются только звуки, которые слышит этот клиент.
- Без мода на сервере действия **других** сущностей опознаются лишь эвристикой по позиции, и при
  неоднозначности мод намеренно ничего не подменяет.
- `item.trident.throw` привязан к только что созданному снаряду: если клиент ещё не знает об этой
  сущности, ванилла отбрасывает звук молча. Возврат и попадание трезубца подменяются надёжно.
- Звуки станков и костной муки/воска идут через `levelEvent`, где предмета в точке проигрывания нет
  вовсе — они опираются на самый хрупкий слой резолва.

./gradlew build      # jar в build/libs/
